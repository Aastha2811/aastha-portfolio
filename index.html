How I work

The habits behind the numbers, each with a real example from my work.

Finding the problem

Size the leak in data, then go find the why from people.

  • Start where the numbers drop: which step, which cohort, how big.
  • Ask one question across user calls, in-person conversations and support tickets.
  • Write the problem as a moment in the user's journey, not as a feature request.
In practice

Data showed only ~31% of customers ever reorder. Fifty conversations showed why: everyone judges results at week 2–3, so I built the journey around that moment.

Read the case →
Prioritising

Few bets, each tied to one metric, smallest version first.

  • Rank by impact on the metric that matters against effort; low-effort, high-impact work goes first.
  • Commit to a short list with a success measure for each, and say no to the rest out loud.
  • Keep v1 simple and configurable, so iterating doesn't need a new release.
In practice

Mapped seven problems across the post-purchase journey, then committed only two to leadership: Day 0–7 onboarding and a week 2–3 results check, each with its own metric.

Read the case →
Design decisions

Prototype the real thing, let behaviour pick the winner.

  • Share clickable mockups, not static screens, so feedback is about the actual interaction.
  • Test the variants that matter: visibility, context, placement.
  • When results tie, choose what holds up as a permanent part of the product, and design for the most common screen.
In practice

Tested five versions of a UV widget over two rounds. Two placements tied, so I shipped the one beside the offers, where people decide to buy.

Read the case →
Managing stakeholders

Show, don't describe, and lead with the outcome.

  • Open docs with the business result, not the mechanics behind it.
  • Flag risks early, with evidence: legal claims, broken copy, device-level error data.
  • Say what the data doesn't prove, so trust survives the next result.
In practice

Brought leadership, brand and design to one direction for a launch page within a day, and went from concept to live in about 12 days.
